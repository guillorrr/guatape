# Languages (i18n)

The scaffold ships Spanish (`es`, default) and English (`en`). The SPA and the
API always speak the same language.

## Which language is used

| Who | Order (first match wins) |
|---|---|
| SPA, before sign-in | choice saved in the browser → browser languages → `es` |
| SPA, signed in | the user's `locale` (profile) → as above |
| API | the user's `locale` → `Accept-Language` (the SPA always sends its current language) → `APP_LOCALE` |
| Emails | the recipient's `locale` (`User::preferredLocale()`), whatever the request's language |

Users pick their language in **Mi cuenta** (saved on the profile, `null` =
follow the browser); guests use the picker on the sign-in screens. Admins can
set a user's language from **Usuarios**.

## Writing UI text (SPA)

- Every string lives in `src/frontend/src/locales/<code>.json`, grouped by
  area (`common`, `nav`, `users`, `forms`…). In components: `const { t } = useI18n()`.
- Menu labels (`core/navigation.ts`) and route titles (`meta.title`) are keys.
- Params use `{name}`; plurals use `|` and `t(key, params, count)`.
- **ESLint fails** on literal text in templates (`no-raw-text`) and on keys
  that don't exist (`no-missing-keys`). `locales.spec.ts` fails when a locale
  lacks a key of `es.json` or changes a message's placeholders.
- PrimeVue's own texts (calendars, paginator, aria labels) follow the language
  via `i18n/primevue.ts`; dates and numbers use the language's regional format
  (`core/constants/locale.ts`, `VITE_LOCALE` for Spanish).

## Writing API text

- Framework messages: `lang/<code>/*.php`. Field names in validation messages:
  `lang/<code>/validation.php` → `attributes`.
- The app's own sentences: `__('English sentence.')`, with the translation in
  `lang/<code>.json` (English needs none: the key is the text).
  `TranslationsTest` fails when Spanish misses a framework key or a literal
  `__()` string.

## Adding a language

1. SPA: `src/frontend/src/locales/<code>.json` with every key of `es.json`;
   add `<code>` to `SUPPORTED_LOCALES` and `LOCALE_NAMES` (`src/i18n/index.ts`)
   and its regional format to `INTL_LOCALES` (`core/constants/locale.ts`).
   For PrimeVue texts, add a locale object next to `primevue-locale-es.ts` and
   register it in `i18n/primevue.ts`.
2. API: `lang/<code>/{auth,passwords,pagination,validation}.php` and
   `lang/<code>.json`; add `<code>` to `config/app.php` `supported_locales`.
3. Run the specs: missing keys fail them.
